# 影之刃零 · 卡肉调节 Mod

[![构建与发布](https://github.com/xbunax/pbz_hit_enhance/actions/workflows/release.yml/badge.svg)](https://github.com/xbunax/pbz_hit_enhance/actions/workflows/release.yml)

通过共享命中反馈入口调整卡肉帧数，提供中文调节面板、快捷键呼出和随游戏启动自动加载。可以按原帧数缩放、增加/减少帧数，或固定帧数。默认 **1 倍**，保留游戏原始时长。

## 0.4.0-preview.3 游戏更新后的启动修复

修复新版游戏因可执行文件哈希变化而被加载器跳过的问题。未知游戏版本记录提示后继续加载，实际运行库或接口错误仍停止相应初始化。build 26367565 / CL302256 已验证冷启动加载与同一运行库中的 F8 木桩菜单；卡肉数值的完整新版回归尚未完成。

本项目与 PBZ Damage Test 各自独立安装和发布，本包不包含木桩 Mod。发行 ZIP 仅提供手动复制安装，不再附带 PowerShell 安装/卸载脚本、开发文档和重复说明。DLL、面板 EXE 及其运行依赖仍是必需文件。

### 生命周期与兼容处理

面板随真实游戏进程启动，并在游戏退出或崩溃后自动结束。仅打开面板不会启动游戏；没有游戏时提示后退出。进程绑定使用完整路径、PID 和创建时间，暂停、切换地图或日志停止更新不会触发退出。

同一个 Release 提供 `with-UE4SS` 整合包与 `mod-only` 仅 Mod 包，分别适用于尚未安装和已经安装 UE4SS 的用户。仅 Mod 包包含本项目的面板启动组件，不包含 UE4SS 或游戏根目录代理。外部运行库先做接口能力检查，未知版本会明确标记，失败时停用本 Mod。

## 分武器类别设置（0.4 预览）

“卡肉设置”新增“编辑类别”：全局默认、单手刀剑、双持武器、双手重武器。各类别可以单独选择倍率、增减帧数或固定帧数，并设置自己的上限。勾选“此类别使用独立设置”后覆盖全局；取消后沿用全局。总开关关闭会停止所有类别的调整。恢复默认只重置当前编辑类别。

分类依据是**本次命中的攻击标签**，不是玩家当前装备。当前候选映射：

| 类别 | 支持的 Slash / Stab 攻击标签族 |
| --- | --- |
| 单手刀剑 | TangBlade、BronzeSword、LuanYing、Wood、Iron、ChiZheCanJian、SlitheringSword、CiGuHunDun、ZiMingJian |
| 双持 | DoubleBlade、SnakeDualShort、SnakeDualLong、DualHook、ShuangYue、JadeDualChakram、YaoJu |
| 双手重武器 | LongBlade、Horizontal、ZhanMa、ZhanMaBlade、PoJun、Jigsaw、YanYueDao、BaiYing |

SlitheringSword 另支持配置中存在的 Slap 挥击类型；其他武器不由此泛化到 Slap。

接受上述标签的点分子标签（例如 TangBlade.Player），比较不区分大小写。其他标签、踢击、能量攻击等未分类事件沿用全局。该映射根据提取的反馈规则建立，**已对乱莺剑、白蟒赤练、亡命斩马刀完成分类与固定帧数实测，尚未证明覆盖全部装备**；新武器需要核对实际标签后补充映射。敌人可能共用这些标签，本版仍包含双方匹配命中，不能当作“仅玩家攻击”。暂不支持单件武器或轻、中、重命中分别覆盖。

乱莺剑的 `Slash.LuanYing.Default` 和 `Stab.LuanYing` 已归入单手分类并通过重载后的实测。样本集中在 Shield.Iron 和 Vessel 材质，不能代替肉体命中及所有敌人类型测试。

白蟒赤练的 `SnakeDualShort.Player` 和 `SnakeDualLong.Player`（含 Slash / Stab）均归入双持，不能因 Long 或共用单手卡肉表而划为其他类别。亡命斩马刀的 ZhanMaBlade 归入双手重武器。

一次三类武器实测中共记录 67 次反馈，单手类别 19 次改为 5 帧（其中乱莺剑标签 16 次、TangBlade.Player 3 次），双持 11 次改为 7 帧，双手重武器 10 次改为 9 帧。40 次修改均与紧随其后的下游 Hitreact 消费参数一致，未记录错误；双持原本 0 帧的一次反馈仍为 0。该验证证明这些样本的独立设置路径有效，不是全武器、全材质或完整调用栈验证。5/7/9 为测试值，不作为默认推荐调校。

覆盖审计直接读取了当前版本的 `DT_WeaponData`：33 条记录全部属于这三类（15 / 8 / 10），包含序章、马车战变体和 Placeholder 资源，不能理解为 33 把独立可收集武器。当前为其中 25 条记录建立了候选标签关联（单手 12、双持 6、双手 7）；仅三把完成实战验证，其余是武器类别、资源名称与反馈规则的静态交叉关联，不能据此保证所有招式。

仍缺少可靠标签证据的 8 条记录：红妆鬼斩、白山风雷剑、珠光宝气、邪火、圣母邪扇、魔切、黑魔伤、黑魔伤（序章）。其中包含占位和变体。未知标签继续沿用全局；主武器的能量、踢击等特殊招式也不保证跟随武器类别。范围目前仅为三个主武器类别，煞器保持现有全局回退行为。

“仅记录命中，不修改帧数”优先于全部调整设置，用于核对类别。运行状态页显示最近命中的标签、识别类别、采用设置、原始与结果帧数；这些是最近反馈，不是当前装备显示。类别未启用独立设置时，识别类别与采用设置可以不同。

旧版六项配置可直接读取，原有值保留；第一次通过新版面板保存时自动补齐类别配置。默认类别均沿用全局，新增设置保存在同一个 config.ini 中并原子替换。新版扩展配置不能直接交回 0.3 的旧脚本使用，回退前恢复旧配置备份。

扩展验证顺序：对新武器先开仅记录模式，核对标签与类别，再以独立固定帧数检查下游输出。本次已完成三件武器的固定帧数测试；后续已验证单手 3 倍（32 次）、4 倍（6 次）及双持 3/4 倍（9 次）的下游帧数匹配；本轮尚未实测总开关关闭后的恢复，该行为已有离线回归覆盖。离线测试不代替实战。

## 原始卡肉帧数参考

**同一武器类别没有统一的原始帧数。** 游戏会根据攻击标签、命中强度、受击材质等选择反馈；以下是 Steam build **26266538** 在 2026-10-31 实战采集中的原始 `SlomoData.Frames`，读取的是 Mod 修改前的 `before` 值。每类目前仅列出一把已验证武器，不能视为同类所有武器的固定参数。

| 武器类别（实测武器） | 极轻 VeryLight | 轻 Light | 中 Middle | 重 Heavy | 轻击退 Knockback.Light | 中击退 Knockback.Middle | 重击退 Knockback.Heavy |
| --- | --- | --- | --- | --- | --- | --- | --- |
| 单手刀剑（乱莺剑） | 2 | 3 | 4 | 6 | 4 | 6 | 6 |
| 双持（白蟒赤练，长短形态合并） | 0 | 3 | 4 | 6 | — | — | — |
| 双手重武器（亡命斩马刀） | — | — | 6 | 7 | 4 | 7 | 12 |

表内单位均为游戏内部帧数；“—”表示本轮未采到该组合，**不代表 0 帧或游戏没有该反馈**。这些强度名对应 `Hitreact.Strength.Income.Normal.*` 标签，不等同于手柄轻攻击、重攻击按键。样本材质仅覆盖 `Shield.Iron` 和 `Vessel`，尚未验证这三把武器在全部肉体、敌人和招式上的取值。

白蟒赤练的重命中 6 帧来自 `SnakeDualLong` 样本，不能由此推断双持通用数据表或短形态的重命中也固定为 6 帧。原本 0 帧的反馈仍保持 0，本 Mod 不将其改成非零。

调节时可据此理解差异：乱莺剑一次原始 3 帧的命中，设置 3 倍后为 9 帧；固定为 5 帧则会把原始 3 帧增加到 5，同时把原始 6 帧减少到 5。上文固定 5 / 7 / 9 帧是验证设置，不能当作游戏原值。

这些帧数未换算为现实毫秒，实际停顿表现还受减速倍率与恢复曲线影响。查看面板“运行状态”中的本次原始帧数，可以核对当前招式实际采用的值。

## 下载与安装

打开 [Releases](https://github.com/xbunax/pbz_hit_enhance/releases)，选择同一版本下适合自己的包：

| 包名后缀 | 适用场景 | 安装说明 |
| --- | --- | --- |
| with-UE4SS-windows-x64.zip | 尚未安装 UE4SS | [整合包安装](docs/INSTALL_with-UE4SS.md) |
| mod-only-windows-x64.zip | 已有正常工作的 UE4SS | [仅 Mod 包安装](docs/INSTALL_mod-only.md) |

不要下载 Source code 当作安装包，也不要同时安装两种运行库。使用 SHA256SUMS.txt 核对下载文件。用户无需安装 Python、Visual Studio 或 ReShade。

### mod-only：已有 UE4SS 的用户

1. 确认现有 UE4SS 能正常随游戏启动，然后完全退出游戏和调节面板。
2. 解压名称包含 `mod-only` 的安装包。
3. 将包内整个 **`UnifiedHitstop` 文件夹**复制到现有 UE4SS 实际使用的 **`Mods` 文件夹**，与其他 UE4SS Mod 放在一起：

   ```text
   Mods/
   ├─ 其他Mod/
   ├─ UnifiedHitstop/
   │  ├─ Scripts/
   │  ├─ panel/
   │  ├─ config.ini
   │  ├─ dependencies.json
   │  └─ install-mode.txt
   └─ mods.txt
   ```

4. 在该 UE4SS 实际使用的 `mods.txt` 中添加或修改下面这一项，保留其他 Mod 的条目：

   ```text
   UnifiedHitstop : 1
   ```

5. 正常启动游戏。首次启动时设置面板快捷键，以后面板随游戏自动启动和关闭。

以上操作无需填写固定安装路径。使用自定义 Mods 目录或统一控制列表时，以现有 UE4SS 配置指定的目录和 `mods.txt` 为准；可参考其他已正常加载的 Mod 所在位置。

**升级：**退出游戏，备份原 `UnifiedHitstop` 中的 `config.ini` 和 `ui_settings.json`（若存在），替换新版文件夹后恢复这两个文件，以保留武器设置和快捷键。

**卸载手动安装：**退出游戏，备份配置，将 `UnifiedHitstop` 文件夹移出 Mods 目录，并移除或禁用 `mods.txt` 中的对应条目。共享 UE4SS 和其他 Mod 保留。

**此前使用整合包：**先停用旧整合包加载器，确认独立 UE4SS 已能正常启动，再安装仅 Mod 包，避免两套运行库同时加载。不要根据文件名随意删除其他 Mod 的代理 DLL。旧版迁移或保留外置目录时，按[仅 Mod 包安装说明](docs/INSTALL_mod-only.md)手动更新；发行包不含安装脚本。

### with-UE4SS：尚未安装 UE4SS 的用户

1. 完全退出游戏和调节面板，下载并解压名称包含 `with-UE4SS` 的 ZIP。
2. 在 Steam 中右键《影之刃零》→“管理”→“浏览本地文件”，进入 `platform\steam`，确认该目录内有真实的 `PBZ.exe`。
3. 将压缩包内的 **`dwmapi.dll` 和整个 `PBZHitEnhance` 文件夹**复制到这个 `PBZ.exe` 旁，保持文件夹结构：

   ```text
   platform/steam/
   ├─ PBZ.exe
   ├─ dwmapi.dll
   └─ PBZHitEnhance/
      └─ ue4ss/
         ├─ UE4SS.dll
         └─ Mods/
            ├─ mods.txt
            └─ UnifiedHitstop/
               ├─ Scripts/
               ├─ panel/
               └─ config.ini
   ```

4. 正常从 Steam 启动游戏。首次启动设置面板快捷键，以后面板随游戏自动启动和关闭。

安装只需复制上述 DLL 和文件夹，具体步骤见[整合包手动安装说明](docs/INSTALL_with-UE4SS.md)。如果目标位置已存在其他来源的 `dwmapi.dll` 或已有独立 UE4SS，不要覆盖，改用 `mod-only` 包。

**升级与旧安装迁移：**先备份原 `UnifiedHitstop` 中的 `config.ini` 和 `ui_settings.json`，替换后恢复。若游戏目录已有本项目的 `PBZHitEnhance.ini`，它可能仍指向旧的外置数据目录；使用上述默认手动布局时，将该文件备份并移出游戏目录，使加载器读取旁边的新版 `PBZHitEnhance` 文件夹。原配置若在外置目录，应先从那里备份。

**卸载手动安装：**退出游戏和面板，将本整合包安装的 `dwmapi.dll` 移出游戏目录，即可停止自动加载。`PBZHitEnhance` 文件夹可备份后移出，以保留设置。只处理自己从本包复制的文件。

## 使用

面板有“卡肉设置、快捷键、运行状态”三个页签。它采用深色半透明置顶窗口，适用于**窗口化或无边框**游戏模式。拖动滑块后自动保存，游戏继续运行时约 1 秒内应用到后续命中；首次初始化可能需要数十秒。

| 设置 | 含义 |
| --- | --- |
| 启用卡肉时长调整 | 关闭后，后续命中恢复原始帧数 |
| 按比例缩放 | 原帧数 × 比例；1 倍是原值，范围 0–4 |
| 增加 / 减少帧数 | 在原值上增减，范围 -30–30 |
| 固定帧数 | 符合条件的普通命中使用固定帧数，范围 0–30 |
| 帧数上限 | 修改结果上限，范围 0–30；结果最低为 0 |
| 恢复默认 | 恢复启用状态和 1 倍原始帧数 |

例如原值 4 帧，设置 1.5 倍会变为 6 帧；设置“增加 1 帧”会变为 5 帧。比例 1、增减 0 时保留原值，不额外裁剪。

本版只写当次命中反馈的 `Frames`，保留倍率和曲线。作用于经过共享入口的普通命中，**包含玩家受击**；跳过原本零帧、格挡、其他特殊标签和按持续时间计时的反馈。帧数是游戏内部单位，尚未换算成现实毫秒。日志证明参数传入执行接口，不能代替实际停顿时长测量。本版尚无独立“停顿强度”调节；增加帧数不会同时降低原始减速倍率或改变恢复曲线，因此主观打击感不一定按相同比例增强。未验证所有武器。

隐藏或手动退出面板不会卸载当前游戏中已经加载的 Mod；游戏结束后面板自动结束。面板程序位于 UnifiedHitstop\panel\HitstopPanel.exe，游戏未运行时双击会提示后退出。

## 更新和卸载

退出游戏后按对应安装说明手动更新或卸载。保留原配置与备份，只处理本项目文件。旧脚本安装的用户应先确认 `PBZHitEnhance.ini` 指向的实际数据目录；源码仓库仍保留旧安装维护工具，但本次发行 ZIP 不包含这些脚本。

整合模式可用根数据目录 disabled.flag 跳过加载；两种模式都支持在 UnifiedHitstop 目录创建 disabled.flag 或使用游戏启动参数 --disable-unified-hitstop，下次启动生效。

## 常见问题

- **按快捷键无反应**：确认游戏为窗口化/无边框。手动运行面板程序，在“快捷键”页点击录入，直接按下所需按键并松开，再保存。支持 Insert 等单键、Ctrl+Insert 等修饰组合，以及 A+B 等多个普通键同时组合；也支持方向键、标点键和数字小键盘。左右 Ctrl/Alt/Shift/Win 视为同一个键。按住不会连续开关，需松开整组按键才能再次触发。无关的移动键或媒体键不会阻断快捷键，额外按住未配置的修饰键则不触发。录入支持常规键盘键，不包含媒体键和鼠标键。录入超时或失去焦点会取消，旧快捷键保持有效；录入结果保存前不生效。Windows 保留的系统快捷键可能被系统优先处理；面板不拦截游戏输入，避免选用常用战斗键组合。
- **显示未连接**：检查 DLL 是否放在真实 `platform\steam\PBZ.exe` 旁，文件夹结构是否完整，并等待游戏进入场景。
- **游戏更新后**：游戏版本与已测试版本不一致时，仅记录 `untested_game_warning_continuing` 并继续尝试加载，不再因版本变化自动停用。实际运行库加载或 Mod 接口初始化失败仍会记录错误并停止对应初始化。旧加载器若记录 `unsupported_game_skipped`，需要更新加载器。版本提示不代表新版游戏已经通过兼容验证。
- **找不到运行库或校验失败**：重新解压完整 Release；不要只复制 DLL。检查外置数据路径是否正确。
- **需要日志**：整合加载日志在数据目录的 `logs\loader.log`；面板启动信息在 Mod 目录的 `bootstrap.ini`，兼容故障在 `startup.log`；反馈日志和状态也在 Mod 目录。共享 UE4SS 日志仍由原运行库管理。

## 从源码构建

需要 Windows x64、Visual Studio 2022 C++ Build Tools（包含 MASM）、Windows SDK、CMake ≥ 3.24、Python 3.14（包含 Tk）。

```powershell
python -m pip install -r requirements-build.txt
python tools/build.py
```

产物位于 `dist/`。只编译 DLL 可使用 `python tools/build.py --native-only`。构建时会下载并校验固定版本的 UE4SS 依赖，记录见 `dependencies.json`。

GitHub Actions 在推送 `main` 或创建 PR 时检查构建；推送与 `VERSION` 一致的 `v*` 标签会在通过检查后发布 Release，例如 `VERSION=0.3.0` 对应 `v0.3.0`。工作流也可手动触发构建。
